# Cloud and publication ownership

The existing native Forge queue validates the actual FWD/CAS with its reviewed job contract. Queue replay is exercised by the existing Core publication helper. No new cloud platform, external deployment or production credential was introduced.

publish_reviewed.py orchestrates DRAFT→VALIDATING→VALIDATED→PUBLISHING→PUBLISHED, with explicit FAILED outcomes. Operator configuration names trusted executable/source paths. Model input cannot edit that configuration. Exact local plan approval and native artifact verification precede publication. A successful retry validates existing persisted content; an incomplete/conflicting job is refused instead of inventing completion.

Cancellation/recovery for arbitrary in-flight publication stages and live desktop publishing controls remain incomplete. Forge verification is not world-publication authority. SpatialDB retains asset publication ownership; only the separate existing owner-authorized MutSea path may admit a static reference, and this demo uses a fresh disposable world copy.

Desktop0.3 was assembled from the preserved branding foundation with the upgraded native worker. A second-review publication button is source-wired to the real adapter through exact operator-owned absolute-path configuration; it stays disabled when unconfigured. Foreground validation of these new controls is pending. No model can select the executable/configuration paths or self-approve publication.
